# Аудит пакета `efureev/support`

**Аудит проведён:** 2026-08-23 на ревизии `c0c745e` · **Актуальная версия:** 6.0.0
**Требования пакета:** PHP `^8.5`, `ext-ctype`, `ext-json`, `ext-mbstring`; `ext-intl` рекомендуется

> **Статус.** Все три блока плана (5.2.x, 5.3.0, 6.0.0) реализованы. Из файла удалено всё

## 1. Резюме

Исходный аудит нашёл 65 находок, включая 5 критичных с потерей или порчей данных. Все они закрыты.
Ниже — то, что осталось.

### Текущее состояние (замерено после блока 6.0.0)

| Метрика                      | Было (5.2.0)          | Стало                        |
|------------------------------|-----------------------|------------------------------|
| Тесты                        | 475, «but there were issues!» | **673 зелёных**, 3586 ассертов |
| Покрытие строк               | 81.9%                 | **96.02%**                   |
| Покрытие методов             | 87.9%                 | **94.51%**                   |
| PHPStan                      | level 2, 3 файла исключены | **level 7**, исключён только `URLify` |
| PHPCS                        | 0 errors, 4 warnings  | **0 / 0**                    |

Прогон строгий: `failOnWarning`, `failOnDeprecation`, `failOnNotice`, `failOnRisky`. Deprecation'ы
из зависимостей исключены через `ignoreIndirectDeprecations` — иначе `--prefer-lowest` на PHP 8.5
роняет сборку из-за чужого кода.

### Что осталось нерешённым

Ничего из открытого не приводит к неверным результатам. Три темы:

1. **Дженерики коллекций** — 21 запись в `phpstan-baseline.neon`. PHP не умеет выразить «тот же
   класс с другими параметрами типа» для `static`-фабрики, поэтому `map`, `filter`, `chunk`,
   `groupBy`, `createFrom` читаются как возвращающие свой же тип. Выбросить дженерики — значит
   ухудшить типизацию, а не улучшить. Level 8 с пустым baseline на этих формах недостижим.
2. **Анализ `tests/` под PHPStan** — требует ~200 правок аннотаций в фикстурах.
3. **Мелкие шероховатости API и пробелы функциональности** — разделы 2 и 3.

## 3. Чего не хватает

### 3.1 API — хелперы

**`Arr`:** `sortRecursive()`, `divide()`, `crossJoin()`, `shuffle()`, `whereNotNull()`.

**`Str`:** `padBoth()`, `wrap()`, `title()`, `uuid()`/`ulid()`.
`studly()` намеренно не добавлен: `toCamel()` уже даёт StudlyCase.

**`Json`:** `prettyPrint()`.

**`Number`:** `format()`, `clamp()`, `percentage()`, `humanize()`, `ordinal()`.

**`Bit`:** `toggleFlag()`, `flags(int $mask): int[]`, `hasAll()`/`hasAny()`.

### 3.2 API — коллекции

`median()`, `flip()`, `zip()`, `every()`/`some()`, `countBy()`,
`lazy()`/`Generator`-обёртка для больших наборов.

Для `HashCollection` — `sortBy`, `partition`, `groupBy` по аналогии с `ArrayCollection`.

### 3.3 API — прочее

* `WithEnhances::random()`.
* `Storage`: `merge()`, `only()`, `except()`.
* Отсутствуют как категории: работа с датой/временем, `Uuid`/`Ulid`, `Result`/`Option`,
  `Pipeline`, `Macroable`, `Comparable`, `Money`/`Decimal`, кэш-абстракция. Это не обязательные
  пробелы — но пакет позиционируется как «collection of useful functions», а покрывает только
  строки, массивы и биты.

### 3.4 Инфраструктура

| Что                                                             | Зачем                                                                    |
|-----------------------------------------------------------------|--------------------------------------------------------------------------|
| Загрузка покрытия в codecov или Coveralls                       | сейчас покрытие в CI не собирается вовсе                                 |
| `composer normalize` в скриптах                                 | плагин подключён, скрипта нет                                            |
| `authors[].email`, `support.issues`, `homepage` в composer.json | нет                                                                      |
| Анализ `tests/` под PHPStan                                     | требует ~200 правок аннотаций в фикстурах                                |
| Матрица CI без `ext-intl`                                       | fallback-путь `URLify` покрыт только через рефлексию, но не прогоном в CI |
