## Что оказалось важнее, чем описано в исходном отчёте

Три дефекта при исправлении оказались серьёзнее, чем я их квалифицировал изначально:

1. **`Str::toCamel` не просто не делил слова — он выбрасывал не-ASCII символы.**
   `'ÜberStraße'` → `'berStrae'`, кириллица → пустая строка. Аудит описывал это как «не
   разделяет слова» (P1-5). Тихая потеря данных.
2. **`Arr::dataToArray` возвращал `[]` для обычного объекта**, а через него
   `Json::encode(new stdClass(...))` давал `"[]"`. Ветка была защищена условием, которое в этом
   месте не могло быть истинным. Два теста закрепляли это как ожидаемое поведение.
3. **`URLify::downcode` протекал состоянием между вызовами.** Один вызов с явным языком отдавал
   его карте приоритет до конца жизни процесса. Вскрыл случайный порядок тестов в PHPUnit 13.

Все три нашлись при написании тестов на ранее непокрытый код — не при чтении.

## Осознанные отказы

| Что                                    | Почему                                                                                                                                                                                        |
|----------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| PHPStan level 8 с пустым baseline      | PHP не выражает «тот же класс с другими параметрами типа» для `static`-фабрики. Попытка упростить `createFrom` ухудшила результат: 11 ошибок → 21. 25 записей baseline — это пределы дженериков, не дефекты |
| Полные аннотации в `tests/`            | ~200 правок в анонимных фикстурах и дата-провайдерах ради нулевой пользы. Реальные ошибки типов проверяются, полнота аннотаций — нет                                                            |
| `symfony/string` вместо `URLify`       | У пакета ноль runtime-зависимостей. ICU через `ext-intl` даёт то же качество, когда расширение есть, и не тянет `symfony/polyfill-*` в каждый проект                                            |
| Переименование глобальных функций      | Blast radius несопоставим с пользой. Вместо этого — фасад `Php\Support\Func`, который ничем нельзя перехватить                                                                                 |
| `Str::studly()`                        | `toCamel()` уже даёт StudlyCase                                                                                                                                                               |
| Вынос `Testing/*` в отдельный пакет    | Сломало бы потребителей, использующих трейты в своих тестах. `phpunit/phpunit` объявлен в `suggest`                                                                                            |
| Категории вроде `Uuid`/`Result`/`Money`| Выходит за рамки «collection of useful functions». `Str::uuid()`/`ulid()` добавлены, полноценные типы-обёртки — нет                                                                            |

## Неизмеримое покрытие

Три места не покрываются принципиально, а не по недосмотру:

* **21 строка `if (!function_exists(...))` в `src/Global/base.php`** — исполняются при
  автозагрузке через composer `files`, до старта сбора покрытия. Тела функций покрыты.
* **Пустое тело `Singleton::__clone()`** — исполняемых операторов нет.
* **Ветка `URLify` без `ext-intl`** — в CI расширение установлено; сама ветка проверяется
  отдельным легом матрицы и через рефлексию.
